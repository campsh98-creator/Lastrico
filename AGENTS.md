# Lastrico development operating rules

- Before implementing a new product feature, write a detailed execution prompt under `outputs/` that defines scope, limitations, acceptance criteria, tests, and release conditions.
- Work as an autonomous development team. Delegate independent routing, UX, QA, and research tasks when useful, while keeping one release owner responsible for integration.
- Diagnose and solve recoverable technical problems without stopping for routine implementation choices.
- Do not declare a feature complete after planning, coding, or compiling alone. Continue through automated tests, mobile end-to-end verification, production deployment, and production smoke testing.
- Preserve honest product behavior. Never ship a visual control that does not change the underlying functionality it claims to control.
- External map apps are fallbacks. Lastrico’s selected route and in-app navigation remain the primary experience.
- Preserve user work and unrelated changes. Ask only when new authority, an irreversible action, or a product decision with materially different outcomes is required.
- Keep user-facing communication in Italian, concise, and nontechnical unless technical detail is requested.
