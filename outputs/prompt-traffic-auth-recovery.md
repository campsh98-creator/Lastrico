# Traffic authentication recovery execution contract

Scope: isolate a PR from main for lastrico-preview-437; preserve the pilot and all existing work. Identify credentials with domain-separated SHA-256 only in the private persistent ledger. Never emit secrets, fingerprints or provider error bodies. Status remains read-only and never probes.

Recovery: only a never-before-observed key different from the fingerprint associated with a rejected credential may bypass that authentication lock, once. Persist quota spend and probe claim before network I/O. Never bypass daily/monthly/overlay quotas, 429, failure cooldowns, or an already consumed probe. Serialize provider work so late successes cannot erase another request's rejection. A successful probe stays held until a separate reviewed release; every unsuccessful probe restores a protective lock. Retain fingerprints across restarts and rotations to stop A/B/A replay. Legacy rejection without identity is unverifiable: do not reset it or invent an old identity. Wait for natural expiry to establish identity through ordinary traffic, or obtain independently verified historical fingerprint via a separately reviewed migration.

Validation: mock-only regression tests for rotation, restart, concurrent distinct tiles, legacy migration, replay, quota exhaustion, other breakers, success hold, 401/403/429/500/timeout/bad request failures, cache, SQL persistence and secrecy. Run TypeScript, lint, full unit suite, build and Linux PR CI. Browser/mobile checks must use mocks before live authentication succeeds.

Release gates: CI green and explicit user approval before any deployment. Only isolated preview; preserve ledger and bindings, never delete/recreate the object. Enable preview probe-only configuration to prevent incidental ordinary requests. No more than one real TomTom request after reset, via the ledger; never use the existing two-call direct live-check script. On failure stop immediately; on success inspect only returned/cached flow data. Incident live validation remains deferred because a second request is forbidden. No TLS bypass, endpoint substitution, security agent change, key extraction or quota reset.

Evidence: report root cause vs unverified entitlement hypothesis, tests, provider usage delta, commit SHA, PR/CI links and GO/NO-GO. Deployment and live authentication are pending until authorized and safe prerequisites are met.
